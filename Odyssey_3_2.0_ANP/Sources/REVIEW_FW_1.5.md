# Odyssey-III рабочая прошивка 1.5 ANP: ревью Ethernet, DHCP, RGMII, SDC

FPGA EP4CE55F23C8 · PHY KSZ9031RNX (RGMII, 1000BASE-T) · openHPSDR new protocol (Hermes 10.x)

## 1. Почему не работал DHCP

| # | Где | Проблема |
|---|-----|----------|
| 1 | `network.v` | DHCP-модуль формировал сообщение, но в `udp_send` всегда шли `udp_tx_data/udp_tx_length` от `sdr_send`, IP/MAC назначения — от последнего ПК, `port_ID` SDR добавлялся к порту 68. То есть DISCOVER/REQUEST физически не отправлялись |
| 2 | `udp_recv.v` | Порт 68 → `ST_DONE` («not supported on 10E») — OFFER/ACK отбрасывались |
| 3 | `network.v` | Во время продления аренды `network_state=1` → сброс всего SDR-тракта каждые lease/2; при неудачном продлении — переход на APIPA 169.254.1.1 |
| 4 | `network.v` | Источник IP при DISCOVER — неинициализированный `local_ip` (должен быть 0.0.0.0); 38-битный таймер продления переполнялся при lease > 61 ч |

## 3. DHCP — как теперь работает

MCU присылает IP 0.0.0.0 → DHCP; иначе статический IP.

1. PHY линк есть → `local_ip = 0.0.0.0`, радио в reset (`network_state = 1`).
2. DISCOVER (broadcast, от 0.0.0.0, secs растёт), повтор через 3 с, затем 4 раза через 2 с.
3. OFFER → REQUEST (broadcast, opt 50 = предложенный IP, opt 54 = сервер, сделавший OFFER).
4. ACK → `local_ip`, радио запускается, 2× gratuitous ARP. Таймер продления = lease/2 (12 ч без опции lease, не меньше 60 с), счёт в секундах.
5. Продление: REQUEST unicast на сервер с ciaddr (без opt 50, по RFC 2131), радио продолжает работать. Повторы; не вышло → новый DISCOVER broadcast от 0.0.0.0 (IP пока сохраняется, secs с нуля); не вышло → повтор через 60 с.
6. **Аренда истекла** (сервер так и не ответил) → IP сбрасывается в 0.0.0.0, радио в reset, DISCOVER заново.
7. **NAK**: на REQUEST после OFFER — сразу новый DISCOVER; на продление — IP сбрасывается немедленно, радио в reset, DISCOVER.
8. Принимается только первый OFFER транзакции; server id — из опции 54 (если нет — IP отправителя); опции разбираются в любом порядке, pad/нулевая длина пропускаются; xid, chaddr и magic cookie проверяются; IP применяется только после полностью разобранного ACK.
9. Нет ответа при старте → APIPA 169.254.1.1 (до переподключения кабеля / перезапуска, как в 1.5).
10. Пропал линк → всё сначала (как в 1.5).

## 4. Второй проход (независимое ревью)

| # | Серьёзность | Проблема | Исправление |
|---|-------------|----------|-------------|
| C1 | **критично** | Любой DHCP-ответ (порт 68) перенацеливал поток SDR (`udp_destination_ip/mac/port`) на DHCP-сервер — при продлении аренды поток уходил на роутер | `udp_recv`: адрес назначения обновляется только для не-DHCP пакетов |
| M1 | major | `ip_accept` перезаписывался yiaddr любого пакета до проверки типа | yiaddr во временном регистре, применение в конце сообщения |
| M2 | major | REQUEST отправлялся на каждый OFFER (несколько серверов) | только первый OFFER |
| M3 | major | NAK и истечение аренды игнорировались | обработка в `network.v` (п. 6–7 выше) |
| M4 | major | server id брался из IP отправителя, не из опции 54 (relay) | опция 54 |
| m1–m7 | minor | опции нулевой длины, handshake REQUEST через toggle, синхронизация `dhcp_enable`, secs не сбрасывался, ICMP/ARP не ждали конца кадра, сброс арбитра tx | исправлено |

Осталось (не мешает работе): FCS принимаемых кадров не проверяется; фрагментированные IP-пакеты не отбрасываются; DHCP-сообщения короче 300 байт BOOTP-минимума (все известные серверы принимают); APIPA постоянна до переподключения; `tx_pll_locked` выведен, но не используется (предупреждение Quartus). `tx_pll.v` правлен вручную (areset/locked, c1 = 2000 пс) — если будете перегенерировать в MegaWizard, включите порты areset и locked и фазу c1 = 90°. Пустые `tx_pll.qip`, `ddio_in.qip`, `ddio_out.qip` в корне — наследство 1.5, не используются.

## 5. Компиляция 1 (ETH_LEGACY_RELAX 1)

- Setup tx_clock −3.4 нс: путь `tx_protocol`/длина → `udp_send` → контрольная сумма IP в `ip_send` → `shift_reg` (19 нс логики за один такт). Исправлено: заголовки UDP/IP и checksum посчитаны конвейером (5 регистров), арбитр выдаёт `tx_start` через 8 тактов после выбора протокола (64 нс на кадр — незаметно).
- Minimum pulse width −7.5 нс на `_122MHz_out` (тактовый выход на ЦАП, PLL_inst c0): 3.3-V LVCMOS ограничен 2 мА. Пин переведён на 3.3-V LVTTL 8 мА (как TX-пины RGMII). Ошибка была и в 1.5.

## 5a. Компиляция 2 и 3

- `ETH_LEGACY_RELAX 1`: без ошибок, RGMII RX запас ≈ +0.8 нс.
- `ETH_LEGACY_RELAX 0` (честные 8 нс в доменах 125 МГц): **без ошибок**. Худшие пути: tx_clock +0.52 нс (`sdr_send` state), PHY_RX_CLOCK +0.42 нс (`Tx_specific_CC` → `sec_count`). Неограниченных путей нет. Оставлять 0. Запас небольшой: при добавлении логики в эти домены смотреть их первыми.

## 6. Проверка

Icarus Verilog, `sim/tb_net.v` (модели altddio/altpll, DHCP-сервер, ПК в тестбенче). DHCP-сценарий: DISCOVER (src 0.0.0.0, broadcast, один раз) → OFFER unicast → REQUEST (поля) → ACK broadcast → IP, GARP ×2 → ARP своего/чужого IP → ping 64 байта (своего) и чужого IP → SDR UDP пакет на ПК (порт 1025, адресация, данные) → продление (unicast, ciaddr) → ACK (lease 30 с) → следующее продление без ответа → повторы → DISCOVER от 0.0.0.0, IP сохранён, радио не сброшено → истечение аренды: IP = 0, DISCOVER → OFFER → REQUEST → NAK → немедленный DISCOVER → OFFER → REQUEST → ACK → IP → продление → NAK → IP сброшен, DISCOVER broadcast. Статический сценарий (`+STATIC`): DHCP-трафика нет, GARP, ARP, ping. FCS, IP/ICMP checksum, длины всех кадров проверяются. Оба **PASS**.
